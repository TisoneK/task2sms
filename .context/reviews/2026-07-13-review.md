## 1. Executive Summary

This was the first agent session on the Task2SMS repo. The session bootstrapped the `.context/` agent-memory directory from the `TisoneK/.context` package skeleton, then ran a full discovery + review + fix sweep across the backend (FastAPI + SQLAlchemy + APScheduler) and frontend (React 18 + Vite + TailwindCSS).

Two parallel sub-agents (one per surface) deep-scanned the codebase and surfaced **51 findings**: 26 backend + 24 frontend + 1 dependency regression found during git-log inspection. Of those, **17 were safe to fix this session** and have been committed and pushed. The remaining 34 are architectural, require database migrations, or need design decisions — they are documented in §6 Open Items and mirrored to `.context/tasks/backlog.md` for future sessions.

**Highest-impact fixes shipped:**
- A production deploy that forgot to override `SECRET_KEY` or `WEBHOOK_SECRET` would have silently run with publicly-known signing keys — now refused at startup.
- `python-jose` 3.3.0 (CVE-2024-33664 / CVE-2024-33663) and `jinja2` 3.1.4 (CVE-2024-34064) bumped; Jinja2 autoescape enabled on the email-rendering environment.
- A regression from commit `91e7a01` that re-bumped Vite from 7.3.1 back to 8.0.3 (breaking `npm install` on a clean checkout) reverted.
- Every Pydantic schema now has input length limits; every icon-only button now has an `aria-label`; every authenticated route is now code-split (initial JS bundle 454 kB → 253 kB, 44% reduction).

**Critical risks still open** (backlog, need design): `eval()` on user-controlled monitor expressions (RCE), no SSRF protection on four user-controlled outbound HTTP paths, in-memory APScheduler jobstore loses schedules on restart and re-fires every monitor 5s after every restart, race conditions on counter increments, `str.format()` on user-supplied message templates (sandbox escape). See §6.

## 6. Open Items

Mirrored to `.context/tasks/backlog.md`. Items are grouped by severity; within each group, ordered by suggested next-session priority.

### Critical (need design discussion before implementation)

1. **F1 — `eval()` RCE on monitor expressions.** `app/services/integrations/scraper_service.py:460, 497, 520` evaluate user-supplied `multi_field_expression` and `monitor_conditions[*].comparing_value` via `eval(_py_expr(expr), {"__builtins__": {}}, namespace)`. The `__builtins__: {}` sandbox is bypassable via `().__class__.__bases__[0].__subclasses__()`. Authenticated user → server-side RCE. **Recommended fix:** replace with `ast.parse` + a `NodeVisitor` whitelist (BinOp, Compare, Name, Constant, BoolOp only), or adopt the `simpleeval` library. Needs full rewrite + tests.
2. **F2 — SSRF protection on outbound HTTP.** Four user-controlled outbound paths have no URL scheme validation, no private-IP filtering, and (for the scraper) follow redirects so a public URL returning `Location: http://169.254.169.254/...` bypasses any future IP filter. Locations: `datasource_service.py:19,39`, `scraper_service.py:39,1005`, `webhook_service.py:57`. **Recommended fix:** add `validate_outbound_url()` helper that (1) enforces `scheme in {http,https}`, (2) resolves hostname and rejects private/loopback/link-local IPs, (3) pins resolved IP for the request (no DNS rebinding), (4) sets `follow_redirects=False` or re-validates each redirect. Needs security design review of allowed destinations.
3. **F-C1 — JWT in `localStorage`.** `src/store/authStore.js:6,13,27` stores the JWT in `localStorage`, which is exfiltrable via any XSS. `nginx.conf` has no CSP header. **Recommended fix:** migrate to httpOnly + Secure + SameSite=Strict cookie set by the backend on `/api/auth/login`; add a strict CSP. Needs backend coordination.

### High (architectural — schedule a session)

4. **F8 — In-memory APScheduler jobstore.** `app/workers/scheduler.py:17,167` uses `AsyncIOScheduler()` with default `MemoryJobStore`. On restart, `load_all_monitors()` re-creates jobs and hard-sets `next_run_time=now+5s` — every active monitor fires 5s after every restart, flooding recipients. Also no `misfire_grace_time`. **Recommended fix:** use `SQLAlchemyJobStore` (persisted in same DB), set `coalesce=True, max_instances=1, misfire_grace_time=300` on `add_job`, respect `monitor.last_checked_at` for `next_run_time`.
5. **F9 — Race condition on counter increments.** `task_service.py:118,128` and `scraper_service.py:759-777,824-866` do read-modify-write with no row lock. SQLite has no `SELECT FOR UPDATE`. The `/tasks/{id}/run` endpoint and the scheduled `_run_task` can collide — losing increments and double-sending SMS. **Recommended fix:** use atomic `UPDATE tasks SET run_count = run_count + 1 WHERE id = :id`.
6. **F10 — `create_tables()` vs Alembic.** `main.py:22` calls `Base.metadata.create_all` on startup, then Alembic is supposed to migrate. Two sources of truth for schema. **Recommended fix:** remove `create_tables()` from lifespan in production; rely on `alembic upgrade head` at deploy time. Keep `create_tables` only for tests.
7. **F12 — No JWT refresh / revocation.** Single long-lived access token (24h). No `jti`, no server-side revocation list. Stolen tokens cannot be invalidated. **Recommended fix:** add `jti` claim, a `revoked_tokens` table, and a middleware check. Or adopt short access tokens (15min) + refresh tokens.
8. **F14 — Missing indexes on hot paths.** `alembic/versions/0001_initial_schema.py` and `0002_new_features.py` lack indexes on `notifications(user_id, created_at)`, `tasks(user_id)`, `webhook_deliveries(webhook_id)`, `email_notifications(user_id)`, `whatsapp_messages(user_id)`, `telegram_messages(user_id)`, `scraper_check_logs(monitor_id, checked_at)`. **Recommended fix:** add a new Alembic migration creating these indexes.
9. **F16 — `str.format()` sandbox escape.** `scraper_service.py:929,961` and `task_service.py:88` use `monitor.message_template.format(**context)`. A template like `{value.__class__.__init__.__globals__[SECRET_KEY]}` can read Python globals. **Recommended fix:** use `string.Template` (no attribute access) or jinja2 `SandboxedEnvironment`.
10. **F-H4 — Modal accessibility.** Modals lack Escape-to-close, focus trap, focus restoration, `role=dialog` (the role was added in `5a63ae9` but the keyboard/focus behavior is still missing). **Recommended fix:** consolidate modal boilerplate (F-M4) into a single shared component that handles Escape, focus trap, and focus restoration.
11. **F-H5 — ScraperPage.jsx is 2563 lines.** Wizard + card + log drawer + helpers all in one file. **Recommended fix:** split into `ScraperPage/index.jsx`, `MonitorCard.jsx`, `MonitorFormWizard.jsx`, `CheckLogDrawer.jsx`, `helpers.js`.
